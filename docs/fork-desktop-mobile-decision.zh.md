# 桌面端和移动端目录的去留

**结论（2026-11-23）：保留 `apps/desktop` 和 `apps/mobile` 的源码，只把它们移出构建。**
此前的做法是整目录删除。本文记录改变做法的理由和现在的做法，供以后升级上游版本时参考。

## 背景

二开只提供网页端。裁剪上游功能的原则是"关入口，留代码"：不要的功能只在路由和界面入口关掉，
后端和共享代码不动，以减少与上游的差异。桌面端和移动端曾是这条原则的例外，被整目录删除。

## 两种做法的差别

| | 整目录删除 | 保留源码、移出构建 |
| --- | --- | --- |
| 网页端功能 | 无差别 | 无差别 |
| 镜像构建、安装依赖 | 不装 Electron、Expo 的依赖 | 同样不装（从工作区排除） |
| 变基时的机械冲突 | 上游每改一个被删文件就冲突一次；变基到 v0.12.2 时有 107 个，另有 17 个上游新增文件要手工删掉 | 没有 |
| 变基时的连带清理 | 上游新增的测试、检查脚本会读取这些目录，要逐个清理 | 基本没有，文件在，测试按上游原样通过 |
| 仓库体积 | 少 649 个文件、约 8 万行 | 多出这些不参与构建的代码 |
| 将来启用桌面端 | 要从上游找回目录，再补上期间删掉的接入点 | 加回工作区，再修补二开改过的共享代码 |
| 搜索代码时的干扰 | 没有 | 会搜到桌面端、移动端的同名代码 |

## 取舍

- 删除带来的冲突本身不难（一条命令全删），真正费事的是连带清理。变基到 v0.12.2 时，上游新增了十来处
  依赖这两个目录的内容：各包 `turbo.json` 的测试输入、`scripts/ui-class-groups.mjs` 扫描的目录、
  eslint 与减少动效的测试用例、CI 路径分组等。每个版本都会有新的，而且要靠跑测试才能发现。
- 保留不等于启用。入口照旧关着：网页端不提示下载桌面端，也不提供"在桌面端打开"，镜像里也没有它。
- 桌面端内置本地运行时，用户不用自己安装命令行。保留源码给将来启用留了余地。
- 代价是仓库里多出一批不参与构建的代码，搜索时会有干扰。相对每次升级省下的工作，可以接受。

## 现在的做法

开关只有一处：`pnpm-workspace.yaml` 把 `apps/desktop` 和 `apps/mobile` 排除出工作区。
排除后 pnpm 不为它们解析和安装依赖，`turbo` 的构建、类型检查、lint、测试也都不包含它们。

为了让排除成立，另有三处必须跟着改：

- `pnpm-workspace.yaml` 的 `allowUnusedPatches`：根 `package.json` 仍登记着移动端依赖的补丁，
  排除后这个补丁用不上，不放行的话安装会失败。
- 根 `package.json` 的 `build`、`typecheck`、`test`、`lint`：上游用 `--filter=!@multica/mobile`
  跳过移动端，工作区里已经没有这个包，`turbo` 会因找不到它而报错，所以去掉了这个过滤。
- `.github/workflows/ci.yml` 里同样的过滤，理由相同。

其余与这两个目录有关的文件都和上游一致，包括发布、桌面端冒烟、移动端校验三个工作流。
它们只在手动触发、推送版本标签、推送 `main` 或向 `main` 提合并请求时运行，二开分支上不会自动运行。

有两处因此与实际不符，属于已知情况：

- `make help`、`make up C=desktop`、`pnpm dev:desktop`、`pnpm dev:mobile` 这些入口还在，
  执行时会因工作区里没有对应的包而失败。
- `scripts/brand/generate.mjs` 从桌面端的依赖里取字体，没装桌面端依赖时跑不了。
  只在重新生成上游品牌位图时才用得到。

## 启用桌面端时要做的事

1. 从 `pnpm-workspace.yaml` 去掉排除，重新生成锁文件。
2. 跑一遍类型检查。二开往共享代码里加了功能，桌面端源码没有跟着改，加回工作区后可能要补几处。
3. 打开网页端的桌面端入口：把 `apps/web/platform/deployment.ts` 里的 `desktopApp` 改为 `true`，
   见 [私有部署的开关](fork-deployment.zh.md)。

## 不在本结论范围内

- `server/ee`、`packages/ee`：商业许可证，不授予使用权，必须继续整目录删除。
- 营销页（`apps/web/app/(landing)`、`apps/web/features/landing`）：带上游品牌和对外内容，继续删除。

## 验证

改完后跑过脚本测试、各项质量检查脚本、类型检查、lint 和前端全量测试。上游那些读取桌面端目录的测试
（样式表编译、字体栈、文字对比度、主题锚点、减少动效、图标导入等）都按上游原样通过，不需要为二开改写。
